## Established facts (raw evidence)

### Phase 1: the clipping bug

`scriptcast/__main__.py`, `_segment_from_wav` accepts `tail_ms: int = 150` but never
uses it:

```
def _segment_from_wav(..., speech_threshold: float = 0.04, tail_ms: int = 150) -> SegmentResult:
    ...
    speech_duration_ms = _measure_speech_duration(audio, sr, speech_threshold)   # tail_ms not passed
```

`_measure_speech_duration(audio, sample_rate, speech_threshold=0.04, tail_ms=0)`
(`scriptcast/post_processor.py:54`) therefore uses `tail_ms=0` for every turn reloaded
from disk (unchanged turns on `--precision-insert`, `--regenerate-turns` neighbours,
`--detect-changes`). Freshly synthesized turns go through `process_segment`, which does
receive `tail_ms` (default 150 at the CLI, `--tail-ms`).

`scriptcast-stitch` (`scriptcast/tools/stitch_episode.py`) cuts each clip with
`atrim=end=speech_duration_ms/1000`, so a too-small `speech_duration_ms` drops audio that
is still in the wav.

Measured on a real 95-turn episode (voice: OmniVoice clone, project
`TheOriginalPower`), recomputing `speech_duration_ms` from the wavs on disk with
`threshold=0.03, tail_ms=400`:

```
refit 95 segments, 93 grew
  turn  26  speech_duration_ms 5820 -> 6830  (physical file 6830 ms)
  turn  46  speech_duration_ms 5480 -> 6090  (physical file 6100 ms)
  turn  22  speech_duration_ms 5170 -> 5730  (physical file 5730 ms)
```

Every segment that grew stayed within its physical file length (the function caps at
`duration_ms`). `--regenerate-turns 7 --tail-ms 400` alone fixed only turn 7, because
neighbours are reloaded through `_segment_from_wav` and lose the tail again on every
invocation. The user's observation was "it is not just that one chunk".

Reference implementation of the workaround (read-only):
`/Users/emmanuel/Documents/Theory/TheOriginalPower/Architecting_the_operation/video/refit_tails.py`

### Phase 4: Quiver AI API (from https://docs.quiver.ai/api-reference/introduction)

- Base URL `https://api.quiver.ai/v1`; `Authorization: Bearer <QUIVERAI_API_KEY>`;
  `Content-Type: application/json`.
- Native SVG endpoints: `POST /v1/svgs/generations` (text to SVG),
  `POST /v1/svgs/vectorizations` (image to SVG), `POST /v1/svgs/edits`,
  `POST /v1/svgs/animations`. Also `POST /v1/responses` (stateless, tool-enabled) for
  "open_responses" models such as `arrow-2`. `GET /v1/models` lists models.
- Responses carry `X-Request-ID`; rate limit headers `X-RateLimit-Limit`,
  `X-RateLimit-Remaining`, `Retry-After`. Streaming uses SSE with `reasoning`, `draft`,
  `content` events, terminal `data: [DONE]`.
- Official Node SDK `@quiverai/sdk`. No pricing or free tier was stated on the intro page.
  **Read the individual endpoint pages before writing the client**; the request bodies
  were not captured. Do not guess field names.

## Contract

### Phase 1 deliverables

1. `_segment_from_wav` passes `tail_ms` to `_measure_speech_duration`.
2. New project keys in `scriptcast.toml` (add to `DEFAULTS` in `scriptcast/project.py`;
   unknown keys already raise): `tail_ms` (default **400**) and `speech_threshold`
   (default **0.03**). CLI `--tail-ms` / `--speech-threshold` default to those values
   when the flag is absent. Update the defaults in `__main__.py` (currently 150 and
   0.04, in several signatures) through one source of truth.
3. New tool `scriptcast-refit` (`scriptcast/tools/refit_render.py`, register in
   `pyproject.toml` scripts): `scriptcast-refit outputs/<episode> [--tail-ms N]
   [--speech-threshold X] [--gap-ms N]`. Recomputes `speech_duration_ms` for every
   segment from its wav, rewrites `episode_manifest.json` (keep a `.json.bak` like
   `scriptcast-relayout` does) and, when `--gap-ms` is given, performs the relayout in the
   same call. It must also update `render_state.json` so a later `--precision-insert`
   does not revert it. No synthesis.
4. Tests: a synthetic wav with a decaying tail proves (a) unchanged-turn reload keeps the
   tail, (b) refit grows `speech_duration_ms` but never past `duration_ms`, (c) refit is
   idempotent.
