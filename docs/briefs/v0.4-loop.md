# scriptCast v0.4 Stage production loop: implementation loops

Source spec: [`v0.4-stage-production-loop.md`](v0.4-stage-production-loop.md)
Orchestration rules: [`../STAGE_PRODUCTION_PARADIGM.md`](../STAGE_PRODUCTION_PARADIGM.md)
Agent table: vault `Orchestration/agent-selection-guide.md`

This file defines the loops that build the v0.4 Stage production loop on branch
`v0.4-stage-loop`. Each loop is an implementer prompt followed by a verifier prompt.

- **Session reuse.** Every implementer session ID is recorded in the dispatch log at launch.
  Fixes go to the **same session** (`cursor-agent --resume <chatId>`, `agy --conversation <id>`,
  `codex exec resume <id>`, `kimi -S <id>`). Start a new session only when there is a stated
  reason.
- **The verifier** is the operator or Claude, tool-grounded and persistent across loops. The
  verifier re-runs every acceptance command and reads the output; a self-report is not evidence.
- **Escalation.** Two corrective re-dispatches that still miss acceptance move the unit to the
  escalation lane: Codex xhigh from 2026-11-04, or Claude.

## L1 — `stage-layout` spike (spec A8)

Assigned implementer: **Cursor `grok-4.7-xhigh`**. Ideal: Codex xhigh, which reads a library to
produce a spec and holds one context. Assigned verifier: **operator/Claude, tool-grounded**.

**Motivation.** Scenes today hand-type pixel geometry, which caused nearly every defect on
2026-11-02. FigCraft's `figcraft-layout` and `figcraft-text` crates already build for `wasm32` and
do real auto-layout and text shaping. If one crate can serve Stage (WASM) and scriptCast's tools
(Python), we skip building our own layout engine.

### Implementer prompt (Cursor, `grok-4.7-xhigh`)

```text
Spike: import FigCraft's layout and text engine into scriptCast as a small Rust crate, `stage-layout`,
with a WASM front end for Stage and a Python front end for scriptCast tools. Measure it on one real scene.

Work in the git worktree ../scriptCast-v04-L1 (branch v04-L1). Do NOT run git commands that change state.

Read first:
- docs/briefs/v0.4-stage-production-loop.md, section A8 (the design and the two spike decisions).
- FigCraft at tag v0.14.0 (https://github.com/storytold/figcraft): crates/doc, crates/layout (layout_page,
  the Measure trait), crates/text (font database, shaping, line layout), crates/engine (how engine
  implements Measure with figcraft-text; copy that adapter, do not depend on figcraft-engine).
- The approved scene to reproduce: TheOriginalPower/Architecting_the_operation/video/yt02/stage/min3_7/b/APAGroupDefinitions.tsx
  and its frame outputs/YT02v2_ov/video/stage_runs/ab_v2/e239.jpg.

Part 1: crate. stage-layout/ (Cargo workspace member), depending on figcraft-doc, figcraft-layout and figcraft-text
by git dependency pinned to tag v0.14.0. One function:
  layout(doc_json: &str, fonts: &[FontBytes]) -> String (JSON: { element_id: {x, y, w, h, lines?: [{text, x, y, w}]} })
where element_id is the FigCraft node name. Register the bundled fonts (IBM Plex Sans and Mono from
scriptCast-stage/video/node_modules/@fontsource or the font files we ship) with figcraft-text. If figcraft-text has
no API for adding font bytes, write that down in FINDINGS and use the narrowest workaround.

Part 2: front ends. (a) wasm-bindgen build (`wasm-pack build --target web`), exposing layout(); report the .wasm size.
(b) PyO3 module via maturin (`stage_layout.layout(doc_json, font_paths)`), installable into .venv-voice.

Part 3: one real scene. Express APAGroupDefinitions' final turn-21 layout (definition card, field panel,
derived-illustration tray) as a FigCraft document with auto-layout frames and named layers. Lay it out
through the crate. Write a tiny Stage test scene that positions plain boxes and text lines from the
returned JSON (one span per returned line, white-space: pre). Render one still with the existing
render command (see TheOriginalPower .../yt02/stage/CLOUD_SETUP.md for how Stage renders) and save it
beside e239.jpg for comparison.

Part 4: measurements in stage-layout/FINDINGS.md: wasm size; layout time per call (median of 100);
whether returned line breaks match what Chrome draws for the same text, width and font; any FigCraft API
gaps. Verdict line: "adopt A8", "adopt with changes: ..." or "reject: ...".

Acceptance (run all, paste tails into FINDINGS.md):
  cargo test -p stage-layout
  wasm-pack build stage-layout --target web
  .venv-voice/bin/python -c "import stage_layout, json; print(len(json.loads(stage_layout.layout(open('stage-layout/fixtures/apa_t21.json').read(), [])) ))"
  the rendered comparison still exists.
Report the session's findings and stop. Do not start any other loop.
```

### Verifier prompt (operator/Claude: run these directly)

```text
Verify L1. Re-run every acceptance command in ../scriptCast-v04-L1 and read the output. Then:
1. Diff the dependency pins: figcraft crates must be git-pinned to tag v0.14.0; no figcraft-engine dependency.
2. Open the comparison still next to ab_v2/e239.jpg and judge it by eye: boxes in the right places, text lines unbroken
   where the approved frame is unbroken.
3. Re-time layout() yourself (python -m timeit) and compare it with FINDINGS.
4. Check the line-break claim: render the same text, width and font in Chrome (one Remotion still) and compare
   breaks.
Record the verdict (adopt / adopt with changes / reject) in this file's Active Loops row and in the dispatch log.
Fix rounds go back to the same Grok session.
```

## L4 — `stage-verify`: OCR and pixel read-back (spec C2)

Assigned implementer: **Cursor `grok-4.7-high`**, a new session (different unit). Ideal: Kimi.
Assigned verifier: **operator/Claude**.

### Implementer prompt (Cursor, `grok-4.7-high`)

```text
Build scriptcast-stage-verify, the video counterpart of scriptcast-verify: read rendered stills back and compare them
with the scene's ground truth. Work in ../scriptCast-v04-L4 (branch from v0.4-stage-loop after L2 merged).

Read first: scriptcast/tools/verify_render.py, stress_check.py, check_render_outliers.py (the audio design you are
copying: content read-back, two stages, specialised second check, outlier model), scriptcast/tools/stage_stills.py
(L2), and the fixtures in video/fixtures/verify/{good,bad}/labels.json.

Inputs: stills.json from stage-stills; the scene's declared elements (the data-text / data-shape boxes and strings,
taken from a static-markup render of the scene at the same ms, as the book repo's checks do); the storyboard strings
per cue.
Checks:
1. OCR read-back with tesseract (Apple Vision comes later in L5; keep the OCR backend pluggable): every required
   string present from its cue, absent before; OCR words that map to no declared string or source line are reported
   as undeclared text.
2. Pixel ink per declared container (empty < E%, crowded > C%) and in the border band (any text-coloured ink
   within 70 px of the frame edge or in the notch zones).
3. Density outliers against the good fixtures (text-pixel and ink density per frame; z-score threshold).
Output verify.json (scene, cue, ms, pass/fail, reasons, element ids) and an annotated contact sheet.
Calibrate E, C and the z threshold on the fixtures and document them.

Acceptance: pytest for each check with synthetic images; on the fixtures, every bad frame is flagged for its labelled
defect and every good frame passes (report precision/recall per defect type); runtime per still.
```

### Verifier prompt (operator/Claude)

```text
Run the tests and the fixture evaluation yourself. Open the annotated sheets for three bad frames and confirm each flag
points at the real defect. Run it on one unseen scene (render stills for HostWetware) and judge the flags by eye.
Fixes go back to the same Grok session.
```
