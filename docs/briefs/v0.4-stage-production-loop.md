# Spec: v0.4 Stage production loop (scene grammar, wireframes, verify and repair, review)

**Branch:** `v0.4-stage-loop`, cut from `v0.3-stage`.
**Why:** see `docs/STAGE_PRODUCTION_PARADIGM.md`. The goal is to make each worker's job small and
bounded, so that:
- a design pass and an implementation pass can be run by different models;
- local models can do the implementation;
- generated video is verified against its spec the way `scriptcast-verify` checks audio against its
  script.

**Reference material:** the approved YT02 scenes in the book repo,
`Architecting_the_operation/video/yt02/stage/`:
- `firstminute/` and `minutetwo/`;
- `min3_7/`;
- the colour registry in `equations/`;
- the audit in `tools/layout_audit.ts`.

Port the patterns, never the pixel constants.

---

## A. Scene grammar with automatic layout (`video/src/stage/grammar/`)

A scene is **data**, roughly 30–80 lines of JSON or YAML, validated by a schema. A fixed component
library renders it.

**A1. Schema** (TypeScript types plus a runtime validator).

```yaml
scene: AllportAntipathy
template: definition-figure        # chosen from the template catalogue (A2)
source: "Allport 1954, p. 9 · The Nature of Prejudice"
elements:
  - id: def
    kind: definition-card
    term: PREJUDICE
    text: "antipathy grounded in a faulty and inflexible generalization…"
    cite: "Allport 1954, p. 9"
    paraphrased: true
    enter: t47Antipathy
  - id: field
    kind: group-field             # PersonMark grid, group or member highlight
    members: 6
    accent: race
    enter: t48Group
    states:
      - {at: t48Individual, highlight: member, index: 2}
reveal: sequential                 # or explicit per element
```

**A2. Templates.** Each one is a layout recipe that places its slots automatically:
- `title-card`
- `definition-figure` (a card beside a drawing)
- `triad` (three terms)
- `flow-lanes` (two or three lanes converging on a node)
- `citation` (a source card and a motif row)
- `equation-band` (an equation, term chips and a plot)
- `group-field` (us/them, ingroup/outgroup)
- `comparison` (two columns)
- `list-rack` (a list of items, for example state powers)
- `timeline`

**A3. Components.**
- **Reuse the existing ones:** `PersonMark`, `TermChip`, `EquationTerms`, `ColoredTerm`,
  `CitationCard`, `DefinitionCard`, `PredictiveUpdatePlot`, `PrecisionGauge`, and others.
- **Intrinsic sizing:**
  - every component reports its size from content;
  - containers size to their children;
  - a container cannot render empty.
- **Deterministic text measurement:** no DOM measurement. Ship a glyph-advance table for IBM Plex
  Sans and Mono at the weights we use, generated once from the font files. Text wrapping is then
  computed in pure TypeScript.

**A4. Enforced by construction.**
- The safe area (x 60–1860, y 70–1010) and the notch zones.
- No overlaps: the templates place slots, and nothing is positioned freehand.
- The size floor: body ≥ 28 px, labels ≥ 20 px.
- Every element gets a stable `id` and declared box. These replace hand-written `data-text` and
  `data-shape` markers.

**A5. The escape hatch.** A `custom` element can hold a bespoke drawing component, such as the
Figure 2.3 recreation or the RLC circuit. It sits inside a template slot; it never takes over the
whole frame.

**A6. Overrides.** `overrides.json`, keyed by scene and element id: `{dx, dy, scale, hidden}`. This
is written by the review UI (D2) and applied after layout.

**Acceptance:**
- One approved YT02 minute (turns 6–10 or 11–16) is ported to the grammar.
- It renders within the visual tolerance of the approved frames.
- Each ported scene's spec is at most 80 lines.

### A7. Alternative layout engine: FigCraft (evaluate before building A3's text measurement)

Building A3's glyph-advance table and our own auto-layout may be unnecessary. FigCraft's headless
CLI (`figcraft-cli`) already does auto-layout and text layout. See the paradigm doc §6. The
pipeline would run:

1. **Design pass.** The designer writes a FigCraft script per scene (`figcraft-cli run`). It uses
   named layers matching the element ids, and auto-layout throughout.
2. **Wireframe review.** `figcraft-cli render` produces the wireframe, replacing B. The author can
   hand-edit in the FigCraft app, replacing D2's drag overrides.
3. **Layout export.** `figcraft-cli info --json` gives the resolved boxes per element id, saved as
   `layout/<scene>.json`.
4. **Stage rendering.** Stage reads `layout/<scene>.json` for positions and sizes, and keeps
   ownership of drawing, motion, cue reveals and equation pulses.

**Spike first.**
- Rebuild one approved scene (for example `APAGroupDefinitions`) through steps 1–4.
- Compare it with the approved frames.
- Measure how many script tokens the designer needs, against a grammar spec.
- **Pick A3 or A7 from the result.**

## B. Wireframe mode

- `STAGE_WIREFRAME=1` renders any scene spec as grey boxes, with element ids, roles and cue words
  as labels, and the reveal order numbered.
- This is the **design pass** deliverable. The author approves the wireframe before any
  implementation work.
- `stage-wireframe <spec> --cues` writes one still per cue, plus a contact sheet.

## C. Verify and repair (the video counterpart of `scriptcast-verify` and `scriptcast-repair`)

**C1. `stage-stills`.** Render stills at `cue + 700 ms` and at the end of each scene, for given
scenes. It is cheap, and it is the only render the loop needs.

**C2. `stage-verify`, a read-back against the spec.**
- **OCR:** read every still on-device, with Apple Vision through a small Swift helper in `swift/`.
  Fall back to tesseract, which videolab already uses.
- **Strings:** each required string is present from its cue and absent before it. No undeclared
  text: OCR words must map to spec strings or source lines.
- **Pixel ink:** measure the ink inside each declared container. Flag empty (< x%) and crowded
  (> y%). Also measure ink in the border band.
- **Density outliers:** flag text and ink density far from the approved scenes' distribution, the
  way `check_render_outliers` uses speaker rates.
- **Output:** `verify.json` (per scene, per cue: pass/fail with reasons) and a contact sheet with
  flags drawn on it.
- **Two stages:**
  1. The OCR and pixel sweep covers everything.
  2. Only flagged stills go to the critic (C3).

**C3. `stage-critic`.**
- Sends flagged stills plus the rubric to an OpenAI-compatible VLM endpoint, which is local on an
  M3 Ultra or hosted.
- The rubric checks for:
  - filler text;
  - empty containers;
  - balance;
  - premature reveals;
  - the picture carrying the idea;
  - the house style.
- It returns structured defects with element ids.
- **Calibration:** run it on the labelled YT02 frames, accepted and rejected (`stage_runs/*` with the
  author's notes), and report agreement.

**C4. `stage-repair`.**
- Gathers the verify and critic defects plus the author's notes (D1) into one batched defect list.
- Resumes the **builder session** recorded in the dispatch log, re-verifies only the failing
  scenes, and stops after `--max-passes 2`, then escalates.

## D. Review UI in the Stage player

**D1. Select and annotate.**
- Pause, click an element (its id comes from A4), and type a note.
- Saved as `review/notes.json`: `{scene, element, ms, cue, note, author, status}`.
- `stage-repair` consumes it.

**D2. Drag and resize.**
- Moves and resizes are written to `overrides.json` (A6), with no code change.
- Every note and override also becomes labelled data for the critic fine-tune.

## E. Dispatch tooling

**`stage-dispatch`** is a wrapper around the worker CLIs (codex, cursor-agent, kimi, agy). It:
- builds flag lists safely;
- writes the brief header (checkpoint hash, owned files, the author's dirty paths);
- records the session ID in the dispatch log;
- with `--resume`, continues an existing session;
- with `--worktree <branch>`, isolates parallel workers.

## F. Order of work and owners

1. **A and B** (grammar, templates, wireframes): one strong model, Codex Sol high from 2026-11-04,
   in one resumed session. Port one approved minute as the reference.
2. **C1 and C2** (stills, OCR and pixel verify): a standard-tier worker, against the labelled
   frames.
3. **E** (dispatch wrapper): small, mechanical.
4. **D1** (select and annotate); then **C3 and C4** (critic and repair) once a VLM endpoint exists;
   then **D2** (drag overrides).
5. **Then run the experiments queue** in the paradigm doc §7, on turns 63+.

**Done means:**
- the reference minute renders from specs;
- `stage-verify` flags the known-bad YT02 frames from 2026-11-02 and passes the approved ones;
- the author can annotate in the player and see the notes reach a resumed builder session.
